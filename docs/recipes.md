# Рецепты

Рецепт — файл YAML, который целиком описывает один запуск генерации: исходный набор, часть набора, зерно
генератора случайных чисел, набор объектов и что из них сделать (сцены, ленты или то и другое). Рецепт
выполняется без интерфейса:

```powershell
ir-line-synth generate recipe.yaml                 # сохранить в output рецепта
ir-line-synth generate recipe.yaml --output D:\out # сохранить в другую папку
ir-line-synth generate recipe.yaml --dry-run       # всё построить и проверить, ничего не записывать
ir-line-synth verify D:\out --data D:\datasets\main_flow
```

Правила сцен и лент — те же, что отправляет страница (автогенератор и лента), поэтому работу, сделанную в
интерфейсе, можно записать рецептом. Пример: [examples/recipe.yaml](examples/recipe.yaml).

## Пример

```yaml
recipe: 1                        # версия формата рецепта
data: ../datasets/main_flow      # исходный набор: папка с data.yaml или сам файл (путь от рецепта)
output: ./synthetic_train        # куда сохранять (путь от рецепта); вне исходного набора
split: train                     # часть набора: все источники и всё сохранённое — только из неё
seed: 17                         # единственное зерно запуска

objects:                         # набор объектов; нужна хотя бы одна из двух частей
  real:                          # целые реальные объекты части (обрезанные краем кадра не берутся)
    kinds: [blob, long, short, rolling, swinging]
    limit: 300                   # не больше стольких, случайный выбор от зерна
  generated:                     # новые объекты: реальный объект, воспроизведённый с другим движением
    - kind: rolling
      count: 30
      limits: {noise_max: 0.1, stripes_max: 0.2}
      accept: filter             # filter — только принятые фильтром; all — все
    - kind: swinging
      count: 30

scenes:                          # партия кадров по правилам автогенератора
  images: 100
  rules: {count_min: 4, count_max: 9, max_iou: 0.15, background_mode: generated}

tapes:                           # длинные записи по правилам ленты
  count: 2
  rules: {length: 2000, objects: 80, layout: clusters}
  values: levels                 # levels — коды 0–255; intensity — доли 0–1
  header: false                  # строка заголовка в CSV сигнала
```

## Ключи

| Ключ | Обязателен | Смысл |
|---|---|---|
| `recipe` | да | Версия формата, сейчас `1`. |
| `data` | да | Исходный набор (папка с `data.yaml` или файл с разделом `data`). |
| `output` | да | Папка вывода: пустая или уже созданная этой программой, вне исходного набора. |
| `split` | да | `train`, `val` или `test`. Объекты, фон и сохранение — только из этой части. |
| `seed` | да | Целое 0…2³²−1. Из него выводятся зёрна всех шагов (см. ниже). |
| `objects.real.kinds` | нет | Виды реальных объектов: `blob` (обычный), `long` (медленный проход), `short` (быстрый), `rolling` (перекатывание), `swinging` (качание). По умолчанию все. |
| `objects.real.limit` | нет | Не больше стольких реальных объектов. |
| `objects.generated[]` | нет | Новые объекты: `kind`, `count` (1…1000), `limits` (наибольшие силы несовершенств `noise_max`, `hotspot_max`, `stripes_max`, `dropout_max`, по умолчанию 0), `ratio` (допустимое отношение длины к ширине для `blob`, по умолчанию `[1.25, 5.0]`), `accept` (`filter` или `all`, по умолчанию `filter`). |
| `scenes.images` | со `scenes` | Число кадров (1…1000). |
| `scenes.rules` | нет | Правила автогенератора, см. ниже. |
| `tapes.count` | с `tapes` | Число лент (1…1000). |
| `tapes.rules` | нет | Правила ленты, см. ниже. |
| `tapes.values`, `tapes.header` | нет | Формат CSV сигнала. |
| `background.id` | при `background_mode: fixed` | Кадр части `split`, на который ставятся объекты всех сцен. |

Нужен хотя бы один из разделов `scenes` и `tapes`. Часть набора, зерно и число кадров задаются один раз на
весь рецепт: внутри `rules` ключи `split`, `seed`, `background_split` и `images` запрещены.

### Правила сцен (`scenes.rules`)

| Правило | По умолчанию | Смысл |
|---|---|---|
| `count_min`, `count_max` | 1, 3 | Добавляемых объектов на кадр. |
| `max_iou` | 0.15 | Наибольшее перекрытие рамок (IoU). |
| `blending` | replace | Наложение: `replace`, `max` (датчик видит ближайшую поверхность), `additive`. |
| `insertion` | mask | Вставка по маске (`mask`) или рамкой целиком (`box`). |
| `edges`, `blur_radius` | hard, 0.8 | Край вставки: резкий или размытый с этим радиусом. |
| `flip_x`, `flip_y` | true, false | Случайное отражение поперёк линии / по времени. |
| `rotation_degrees` | 10 | Случайный поворот ± градусов. |
| `brightness_min`, `brightness_max` | 0.9, 1.1 | Множитель яркости. |
| `gamma_min/max`, `contrast_min/max` | 1, 1 | Изменение соотношений яркости пикселей. |
| `noise_max`, `gradient_max`, `erode_max` | 0 | Шум, градиент освещения, выкрашивание краёв. |
| `shade_probability`, `shade_max` | 0, 0.5 | Затемнённое пятно: вероятность и наибольшая сила. |
| `background_mode` | fixed | Фон: `fixed` (`background.id`), `real` (случайный реальный кадр), `generated` (новый из пустых каналов). |
| `background_block_min/max` | 2, 8 | Каналов в блоке сгенерированного фона. |
| `background_level_min/max` | 1, 1 | Множитель уровня сгенерированного фона. |
| `unique_per_image`, `unique_source`, `balanced` | true | Без повторов объекта в кадре; не больше одного объекта от одной реальной рамки; сначала реже использованные. |
| `morph_reseed` | true | Новые несовершенства нового объекта при каждой вставке. |

### Правила лент (`tapes.rules`)

| Правило | По умолчанию | Смысл |
|---|---|---|
| `length` | 400 | Длина ленты, опросов (40…20000). |
| `objects` | 20 | Число объектов (0…1000); те, которым не нашлось места, не ставятся, и запуск об этом сообщает. |
| `layout` | random | Расположение: `random`, `even` (равные шаги), `clusters` (группы). |
| `jitter` | 0.3 | Для `even`: разброс в долях половины шага. |
| `cluster_min`, `cluster_max`, `cluster_spread` | 2, 4, 6 | Для `clusters`: объектов в группе и разброс группы, опросов. |
| `background` | generated | Фон ленты: `generated` или `blank` (нули). |

Кроме того, ленте подходят правила объектов из таблицы сцен (отражения, поворот, яркость, вставка, наложение,
`max_iou`, несовершенства, параметры фона). Правила кадра (`count_min`, `count_max`, `images`,
`background_mode`, `unique_per_image`, `unique_source`) у ленты фиксированы.

## Зёрна шагов

Каждый шаг запуска получает своё зерно, выведенное из `seed` рецепта (`numpy.random.SeedSequence([seed, шаг,
номер])`): выбор реальных объектов, каждая партия новых объектов, партия сцен, каждая лента. Поэтому
изменение одного раздела рецепта не меняет случайные числа других шагов (хотя сцены и ленты, конечно,
зависят от набора объектов), а тот же рецепт на тех же данных и той же версии программы даёт те же файлы
(имена файлов случайны, содержимое — нет; это проверяется тестами).

## Отбор без просмотра

В интерфейсе кандидатов отбирает человек. При запуске рецепта сохраняется всё, что допускают правила:
отбором служат правила размещения, фильтр новых объектов (`accept: filter`) и проверка дубликатов. Кадр,
уже имеющийся в выводе, не сохраняется повторно и попадает в список пропущенных.

## Запись о запуске

Каждый запуск (кроме `--dry-run`) пишет в `runs/` вывода два файла:

- `run_<время UTC>_<начало SHA-256 рецепта>.json` — версия программы, рецепт и его SHA-256, путь к
  исходному набору, профиль линии, размер набора объектов, сколько сделано, сохранено и пропущено (с
  причинами), отказы правил, примечания;
- `run_<…>.recipe.yaml` — копия файла рецепта.

Каждый сохранённый кадр и лента, как и при работе в интерфейсе, хранит своё полное описание, по которому
команда `verify` строит его заново и сравнивает с файлами.
